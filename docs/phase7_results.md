## Comparison to literature reference points (PLAN.md)

These are reference points only, per CLAUDE.md's evaluation philosophy — never tuned
toward, and accuracy is never the headline metric on this ~0.17%-positive dataset (all six
arms score >94% accuracy trivially; see the table above for why that number is included
only for context, not as a result to lead with).

- Literature: ~91% federated / ~95% centralized **accuracy**. Ours: federated_augmented 99.8%, centralized_augmented 99.4% — both exceed the literature figures, but accuracy is not a meaningful comparison here (see above); included for completeness only.
- FedFraud: F1 0.90 / AUC 0.96 under non-IID conditions. Ours (federated_augmented): F1 0.61 / AUC 0.95. AUC is close to the reference point; F1 is well below it. Reported honestly as a gap, not smoothed over — plausible contributors, none confirmed: (1) this project's non-IID partition is deliberately more extreme than typical benchmarks (Banks C/D hold only 15 real fraud rows each, by design — see D5), (2) the CPU-only small-scale run here uses far fewer local epochs/rounds than a literature-scale setup, (3) 2 of 4 banks' synthetic augmentation batches were rejected by the shared validation layer in Phase 3 (Banks B and C), so federated_augmented's real advantage over federated_real is carried entirely by Banks A and D's validated synthetic data, not all four.

## Headline finding

**federated_augmented** is the best-performing arm on F1 (0.6146), ahead of federated_real, both isolated arms, and both centralized arms — despite only half the banks' augmentation surviving Phase 3 validation. federated > isolated on every metric, matching the literature's qualitative expectation that federation beats fully isolated training. centralized_real has the lowest F1 despite the strongest AUC, a genuine class-imbalance/decision-threshold artifact investigated and explained in the Phase 4 progress log — not a bug, and not hidden.
